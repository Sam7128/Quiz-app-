## 2. Benchmark Scenarios

### Scenario A: Cold Start (首次無快取冷啟動)
- **目標**: 驗證 `index.html` 的 pre-paint theme bootstrap 在冷啟動時對首屏總延遲的衝擊是否維持在微秒級。
- **測試條件**: 清空瀏覽器快取，無痕模式啟動，`localStorage.getItem('mindspark_theme') = 'dark'`。
- **預期結果**: 
  - Inline script 執行完畢時間 < 1.5ms。
  - `document.documentElement` 在第一次 Frame Paint 前完成 class 設定。
  - FOUC 白閃次數: 0 次。

### Scenario B: Baseline (日常平穩做題與讀取)
- **目標**: 測量 100~300 題常見題庫在做題卡中的順暢度與反序列化效能。
- **測試條件**: 包含 250 題的題庫，常態連續作答 50 題。
- **預期結果**:
  - `getQuestions` 首次載入時間 < 5ms。
  - 答題音效與自動切題間隔平滑無卡頓，記憶體曲線呈平穩直線。

### Scenario C: Peak Load (極限萬題匯出壓力測試)
- **目標**: 驗證大題庫匯出改用 Blob Object URL 後的極限記憶體與下載表現，以及快速連點防抖能力。
- **測試條件**: 生成包含 5,000 題（含解析與選項，約 8.5MB JSON）的巨大題庫，點擊匯出，並模擬 5 次快速連續點擊。
- **預期結果**:
  - `JSON.stringify` 耗時 < 45ms。
  - `new Blob` 與 `URL.createObjectURL` 耗時 < 15ms。
  - 記憶體瞬時上升 < 20MB，並在 1000ms 的 `revokeObjectURL` 觸發後全數釋放恢復基準線。
  - 連點防抖策略生效，僅生成 1 個 Object URL，無多餘定時器累積。
  - 無瀏覽器 URL 截斷錯誤，無 OOM 崩潰。

### Scenario D: Sustained Stress (長時間作答與記憶體洩漏檢測)
- **目標**: 檢驗答題提示音改為 Howler 單例後，在長時間作答下是否存在音訊節點或定時器洩漏。
- **測試條件**: 模擬連續答題 1,000 次（每秒 2 題），交替觸發正誤提示音。
- **預期結果**:
  - JS Heap 記憶體增長在作答完畢 GC 後回歸基礎值（漂移率 < 3%）。
  - 音訊節點實例始終維持固定 Howl 單例，無累積建立。
  - 主執行緒無未清除之孤兒定時器。

### Scenario E: Chaos / Fault Injection (異常資料注入與容錯)
- **目標**: 驗證極端畸形資料與例外注入下的防禦降級機制。
- **注入情境**:
  1. **BOM 髒資料**: 傳入開頭連續 10 個 `\uFEFF` 之 JSON 檔案。
  2. **畸形資料陣列**: 傳入包含 100 題 `options: null`、50 題缺少 `question` 的陣列。
  3. **Storage 存取受拒**: 模擬無痕模式拋出 `SecurityError`。
- **預期結果**:
  1. BOM 順利洗淨，解析成功率 100%。
  2. 150 題壞題全數被安全隔離，未拋出任何 Uncaught TypeError，有效題目完整保留。
  3. 頁面優雅降級至淺色模式，控制台無阻塞性紅字錯誤。

### Scenario F: Data Scale Progression (資料規模階梯遞增)
- **不同題庫規模下的反序列化與 Guard 校驗耗時矩陣**:

| 題目數量 | JSON 檔案大小 | `JSON.parse` 耗時 | `parseQuestions` 耗時 | 總延遲 (Total) | 是否符合預算 |
|:---:|:---:|:---:|:---:|:---:|:---:|

## 3. Memory Leak Detection Protocol

1. **基準快照 (Baseline Snapshot)**: 進入做題頁面後，手動觸發 Chrome DevTools GC，記錄 Heap Size。
2. **負載迭代 (Load Iteration)**: 連續執行 100 次作答、20 次題庫匯出、10 次深色模式切換。
3. **終態快照 (Post-Test Snapshot)**: 等待 1500ms（確保 Object URL revoke 完畢），再次手動觸發 GC。
4. **合格判定 (Pass Criteria)**:
   - `Heap Growth = (Post-Test Heap - Baseline Heap) < 2 MB`。
   - `Detached HTMLAnchorElement` 數量為 0。
   - `Blob` 引用計數為 0。

## 4. Resource Contention Map

- **主執行緒與 UI 渲染**:
  - `parseQuestions` 在大於 1,000 題時可能占用主執行緒 ~15ms。由於反序列化僅在切換題庫時執行一次，不與做題動畫衝突。
- **音訊執行緒與作答動畫**:
  - Howler.js 音訊解碼與播放非同步進行，答對動畫（Framer Motion）維持獨立 60FPS。
