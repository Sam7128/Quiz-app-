## 3. Benchmark Scenarios

### A. Cold Start

**Setup:** Fresh Chromium context, cache disabled, isolated `mindspark_theme=dark`; repeat for `light`, `system` match/mismatch, and storage/matchMedia exceptions.

**Pass criteria:** Bootstrap p95 < 2 ms; dark class exists before module execution; zero FOUC in trace; exception runs load without uncaught errors and use light.

### B. Baseline

**Setup:** 250 synthetic questions, 50 answer submissions, enabled and disabled SFX runs.

**Pass criteria:** Initial `getQuestions` p95 < 5 ms; no uncaught errors; disabled SFX makes zero Howler play calls; enabled SFX makes one feedback call per answer; no long task > 100 ms.

### C. Peak Export

**Setup:** 5,000 synthetic questions with explanations/tags, about 8 MB JSON, isolated download context. Run five sequential and five rapid-click exports.

**Pass criteria:** `JSON.stringify` and Blob initiation each meet the 100 ms p95 budget; no Data URI; every URL revoked exactly once within 1.5 s; peak heap < 75 MB and returns within 2 MB of baseline; documented rapid-click policy is enforced.

### D. Sustained Stress / Soak

**Setup:** One mounted QuizCard, 1,000 answer cycles at two per second, alternating correct/wrong and toggling SFX every 100 cycles.

**Pass criteria:** Post-GC heap growth < 2 MB; no more than two active quiz Howls; all Howls stop active playback on unmount while maintaining resident singleton buffer; no detached anchors, orphan timers or unhandled errors; answer completion is 100%.

### E. Chaos / Fault Injection

| Fault | Injection | Pass criteria |
|---|---|---|
| Ten leading BOMs | Prefix valid JSON with ten `\\uFEFF` values | Same questions as BOM-free input. |
| 150 malformed records | 100 `options:null`, 50 missing `question`, plus valid records | Valid records survive; no uncaught error; warnings bounded and non-sensitive. |
| Invalid root | `null`, object, scalar, invalid JSON | `getQuestions` returns `[]`; active bank unchanged. |
| Blob failure | Throw from `Blob` or `createObjectURL` | Existing error path; no state mutation or uncaught error. |
| Howler failure | Throw load/play and fire callbacks | Answer, score and navigation complete; cleanup idempotent. |
| Storage failure | Throw `SecurityError` from theme/SFX reads | Page remains usable; light theme fallback. |

## 5. Memory Leak Detection Protocol

1. Open an isolated Chromium context and record a forced-GC baseline where supported.
2. Run 100 exports, 1,000 answer cycles and 10 theme changes.
3. Wait 1.5 seconds after the final export so delayed revocation runs.
4. Unmount QuizCard and force GC again.
5. Compare heap, detached anchors, active Howl instances, live URLs and pending timers.

**Pass:** post-GC heap growth < 2 MB, zero detached anchors, zero live export URLs, active quiz Howls capped at 2 (resident singletons, zero growth), and no timer/listener growth.

## 6. Resource Contention Matrix

| Resource | Competing modules | Risk | Mitigation |
|---|---|---|---|
| Main thread | `parseQuestions`, `JSON.stringify`, React render | MEDIUM long tasks for large banks | Measure 1K/5K budgets; reject unsupported sizes gracefully. |
| JS heap | Parsed JSON, Blob payload, browser download | MEDIUM temporary coexistence | Blob URL, delayed revoke, heap gate, rapid-click policy. |
| Audio | QuizCard and BattleArena | MEDIUM shared lifecycle | Resident singleton for quiz cues; cleanup stops playback without unloading buffer. |
| Storage | Theme bootstrap, ThemeContext, SFX and bank reads | LOW restricted/repeated access | try/catch, allowlist, isolated tests. |
| Console | Guard warnings | LOW log flood | Bounded detailed warnings plus aggregate count. |

## 7. Degradation Under Sustained Load

| Load | p95 target | Error rate | Resource limit |
|---|---|---:|---|
| 1x: 250 questions | Baseline SLO | 0% uncaught | Heap < 45 MB |
| 2x: 500 questions | <= 1.5x baseline | 0% uncaught | Heap < 50 MB |
| 5x: 1,250 questions | <= 2x baseline | 0% uncaught | Heap < 60 MB |
| 20x: 5,000 questions | Scenario F target | 0% uncaught or graceful error | Heap < 75 MB |

**Breaking point:** first input size exceeding the 250 ms long-task or 75 MB heap limit. Report the actual question count and failure mode; do not invent a server concurrency number for this SPA.

## 9. Benchmark Harness Specification

### 9.1 Environment

| Component | Specification |
|---|---|
| OS | Windows 11 or documented equivalent |
| Runtime | Repository-supported Node.js; record `node --version` |
| Browser | Playwright Chromium; record exact version |
| App | Vite production build served locally |
| Runner | Vitest plus Playwright Chromium |
| Data | Synthetic fixtures and isolated browser context only |
| Metrics | `performance.now()`, traces, heap snapshots where supported, URL/Howler/warning spies |

### 9.2 Execution Protocol

1. Run `npx tsc --noEmit`, targeted tests and production build.
2. Generate 100/500/1K/5K synthetic fixtures without touching real storage.
3. Run A, B, C, D, E and F in separate isolated contexts; repeat F three times per size.
4. Capture p50/p95/max, heap, warnings, URL count, Howl count and uncaught errors.
5. Store timestamped traces/metrics only under test output; clean only that output directory.
6. Mark the harness PASS only when every scenario row below passes.

### 9.3 Success Criteria Summary

| Scenario | Pass | Fail |
|---|---|---|
| A Cold Start | Bootstrap p95 <2 ms, no FOUC, exception runs load | Uncaught error, late class or FOUC |
| B Baseline | 250-question load and 50 answers meet latency/audio rules | Answer regression, error or long task >100 ms |
| C Peak | 5K export meets budgets and URLs revoke exactly once | Data URI, URL leak, OOM or threshold breach |
| D Soak | 1K cycles, heap growth <2 MB, cleanup complete | Leak, instance/timer growth or incomplete answers |
| E Chaos | Every injected fault is contained and data unchanged | Uncaught exception, blocked answer or mutation |
| F Data scale | Each size meets its row targets and reports p50/p95/max | Missing metrics or degradation before 5K |

**Gate 7: PASS.** Scenarios A-F each have measurable setup and pass/fail criteria.
