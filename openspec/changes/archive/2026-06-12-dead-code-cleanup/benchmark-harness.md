## 1. Performance Objectives & SLOs

> **Contextual Justification**: 此變更為「死碼清理」，不涉及資料庫層、網路架構或業務邏輯的重構。因此，不需要進行全系統的壓力測試（Soak, Chaos）。然而，由於清理過程中移除了 `export default React.memo(Component)`，存在**嚴重的元件渲染效能退化風險**。因此，本基準測試的核心目標聚焦於前端 React 渲染效能（Render Latency）與無謂渲染（Wasted Renders）。

### Service Level Objectives

| Metric | Target | Warning Threshold | Critical Threshold | Measurement Method |
|--------|--------|--------------------|--------------------|-------------------|
| QuizCard Re-renders | 0 (當 props 不變時) | 1 | >1 | React Profiler / Console count |
| BankManager Re-renders | 0 (當 props 不變時) | 1 | >1 | React Profiler |
| AIPromptGuide Re-renders | 0 (當 props 不變時) | 1 | >1 | React Profiler |
| App Bundle Size (JS) | ≤ Baseline | +50KB | +100KB | Vite build output |

## 4. Execution Protocol

1. **Pre-flight checks**: 在清理執行前（Baseline），切換一次全域主題，使用 React Profiler 記錄 `QuizCard` 和 `Settings` 的渲染行為（應該是被 memoize 的）。
2. **Bundle baseline**: 執行 `npm run build` 並記錄大小。
3. **執行清理**: 依照修改後的 `tasks.md` 執行所有清理任務。
4. **Post-flight checks**: 再次切換全域主題，確認 `QuizCard` 和 `Settings` 依然未被重新渲染。
5. **Bundle validation**: 再次執行 `npm run build`，確認大小未增加。
