Implement tasks from an OpenSpec change with stress test integration.

**Input**: Optionally specify a change name after `/opsx-apply-tested` (e.g., `/opsx-apply-tested add-auth`).

**IMPORTANT**: This workflow invokes the `openspec-apply-with-tests` skill. You MUST read the skill's SKILL.md file at `.agents\skills\openspec-apply-with-tests\SKILL.md` BEFORE proceeding. The SKILL.md defines the complete execution pipeline.

**Steps**

1. **Read the skill definition**
   Read `.agents\skills\openspec-apply-with-tests\SKILL.md` completely. This is NON-NEGOTIABLE.

2. **Execute the skill pipeline exactly as defined**
   Follow the SKILL.md pipeline from Phase 1 through Phase 5.

   - **Phase 1: SELECT** — Identify the target change
   - **Phase 2: DETECT** — Check for stress test artifacts (stress-test-report.md, benchmark-harness.md)
   - **Phase 3: INGEST** — Read all context files (standard + stress test)
   - **Phase 4: IMPLEMENT** — Execute tasks with test-aware guidance
   - **Phase 5: REPORT** — Summarize results

3. **Key Behavior**
   - If stress test artifacts are detected → **TEST MODE**: Implementation proactively addresses stress test findings
   - If NO stress test artifacts → **STANDARD MODE**: Behaves identically to `/opsx-apply`
   - Stress test findings are ADVISORY — they guide implementation quality but do NOT block task completion

**Guardrails**
- Do NOT modify stress-test-report.md or benchmark-harness.md — they are read-only references
- Stress test issues are advisory, not mandatory blockers
- Standard tasks from tasks.md always take priority
- All commands use Windows (pwsh) syntax
