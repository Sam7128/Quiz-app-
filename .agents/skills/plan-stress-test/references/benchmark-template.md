## 5. Memory Leak Detection Protocol

> **Purpose**: Detect gradual memory growth that indicates leaks.

### Test Procedure
1. Run Scenario D (Soak Test) for minimum 4 hours
2. Sample memory metrics every 60 seconds
3. After discarding the first 30 minutes (warm-up), calculate linear regression of memory growth

### Leak Detection Criteria

| Metric | Pass | Marginal | Fail |
|--------|------|----------|------|
| Hourly Growth Rate | < 1 MB/hr | 1–5 MB/hr | > 5 MB/hr |
| Total Growth (4hr) | < 10 MB | 10–50 MB | > 50 MB |
| GC Reclaim Efficiency | > 95% | 85–95% | < 85% |
| Object Finalization Queue | Empty at steady state | < 100 pending | > 100 pending |

### Common Leak Sources to Monitor
- [ ] Event listeners not removed
- [ ] Cache entries without TTL or size limits
- [ ] Unclosed connections / streams / file handles
- [ ] Closures capturing large scopes
- [ ] Circular references preventing GC
- [ ] Growing log buffers or history arrays
